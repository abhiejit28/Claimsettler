## Project 
name is ClaimSettler
## Description
Insurance companies often seen facing challenges in the process of handling insurance claims. Study suggests, an insurance company with business across Auto, Home and commercial businesses receive more than 50k claims. This architecture document intended to propose
GenAI solution to minimize the human efforts and reduce the time to process the claim considering the risk of fraud and repetitive claims.
## Context
For Claim settlement process there are main four stages, Frist, FNOL(First Notice of Loss), which is manually, a reception receives policy holder call of loss or damage and the reception writes down the notes. Second, Claim-Document Validation, where the insurance document and FNOL information scanned and and validates insurance policy is active, the claim made is covered in the policy or not, any earlier claims etc. Third is, Claim Adjuster who invokes fraud test, and in parrallal validates and approves the claim-document validators report. Adjuster is important stage. Fourth is Fraud Finder, manually Fraud detection has limitations, like informatin provided correct or not, duplicate claim, the video shared is fake or not etc. Fraud Finder responds back to Adjuster and Adjuster takes final decision to approve the claim.
## Solution
The Claim Intelligent Platform will expose a RESTful API to receive claim requests. The API includes endpoints for voice request, JSON request, video request, an application form, or pdf/word/text file. The API consumes claim request and sends it FNOL Agent. 
# FNOL Agent
FNOL Agent creates a claim request document. Since there are different formats request can come, to parse and convert the request in plain JSON format there will be different 'skills'. The SKILLS like, for convert voice to text, video to text, scanned application form to read through OCR like tools and find required fields, read pdf/word/text files and extract meaningful data. Skills will use appropriate suitable tools. FNOL sends the generated claim request document to  Knowledge Management Agent with a unique claim ID 
# Knowledge Management Agent
KMA(Knowledge Management Agent) is an independent AI Agent exposed as MCP service. It takes claim document, policy documents, and other insurance company rulebook for different insirance products. All the documents stored in a Vector database. The data pipeline including chunking, embedding, vectorizing and storing to database. Every document has reference to related documents. for example, claim document had policy id of policy document, policy document had product id of insrurance products and its rulebook. Semantic chunking with size 500-700 tokens with 100 tokens overlap. Embedding options to be considered BGE-M3, OpenAI text embedding-3-large or Voyage AI Embeddings. The generated embedding together with original text and associated metadata are indexed into scalable vector database, options like Pinecone, Weaviate, Azure AI Search or pgvector whichever is bet suitable.
KMA is a pure RAG architecture. It has a search flow as well.
# RAG Search or Vector Search Agent
KMA MCP service also useful for queries in matural language. Vector Search Agent(VSA) performs query writing and optimization using LLM to improve retrieval quality by normalizing insurance terminology. The next step is embedding the query to peform Hybrid Search, combining, semantic vector similarity, BM25 lexical search and metadata filtering. The retrived candidates are subsequently passed through a Cross-Encoder Re-ranker (BGE-reranker or Cohere Rerank). Top ranked chunkes , together with their metadata and source citations provided as contentual evidence to LLM to generted a grounded, explainable response. Every response includes references to the originating documents and policy clauses, while prompts, retrieved chunks, model versions, confidence scores and tool invocations are captured within the audit trail to ensure complete tracebility and regulatory compliance.
# Claim adjuster Agent
Claim adjuster agent takes claim request and uses three subagents:
PolicySearchAgent: which searches policy information, insurance products, claim rules etc. This agent communicates with VSA
SimilarClaimAgent: This agent searches past claims which are similar and what actions were taken. This agent communicates with VSA.
FraudAgent: Claim adjuster Agent can invoke the Fraud agent and if resulted into a fraud claim then, Claim adjuster rejects claim and no further action required. See the Fraud Agent below.
PlannerAgent: If the Fraud Agent  detects no fraud then Planner agents takes Policy Search and SimilarClaimAgent response and predicts the claims to be approved or not. For that XGBoost or other classification AI model needs to be trained on the insurance past data.  The result of the model should be reported to claim adjuster and get their approval to accept the model prediction and then this claim data alongwith model prediction should be stored to model training data. In case of model's prediction rejected/revrsed by human claim adjuster then should take improvement notes which should also be stored and used to train the data.
# FraudAgent
Detects whether the claim is fraud or not. It works in two steps. Frist, simple and straight forward, check the rules. If all the provided data meets the rule-engine give go ahead. Second is ML Engine, which has multiple subagents
 RuleEngineAgent: checks rule based fraud.
 Supervised ML model: Using XGBoost ot LightGBM model trained on hisotric data
 The Anomoly Agent: Finding unusual pattern using algorithms like isolation Forest or Autoencoders
 Graph Analysis Agent: utilizes graph databases (e.g., Neo4j) to identify organized fraud rings by analyzing relationships between claimants, vehicles, repair shops, hospitals, witnesses, and service providers.
All subagents responds with detail report. FraudAgent reads the report and generates summarized report with combined confidence score and presents to human claim adjuster. The findings of all subagents updated to KMA.
